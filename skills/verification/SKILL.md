# Verification

验证不是走流程。验证是用事实关门。

没有验证，任务没完成。

## 层级

### 1. 静态检查

- 类型检查。
- 构建。
- 搜索旧入口。
- 搜索旧路径。
- 搜索旧文案。
- 搜索旧事实。

### 2. 自动测试

- 先跑相关测试。
- 再跑完整验证。
- 新能力必须有真实行为测试或机器检查。
- 测试失败先读事实，再改代码。

### 3. 行为检查

- CLI 看真实输出。
- Web 看页面、服务响应、DOM 或 WebSocket。
- Telegram 看输入分类、文件传输、输出队列和中断事实。
- Recovery 看 control plane、status、wake、session events。

### 4. 发布检查

- `npm pack`。
- 安装 packed tarball。
- 执行 `kitty --version` 或等价 smoke。
- CI 覆盖目标系统和 Node 版本。

## 失败处理

- 失败就是事实。
- 先读失败。
- 再判断原因。
- 再修。
- 修完重跑。

不要隐藏失败。不要把没验证说成没问题。

## 收口

最终回复必须说明：

- 跑了什么命令。
- 结果是什么。
- 没验证什么。
- 风险是什么。

如果全部闭环，就直接说无剩余已知风险。
