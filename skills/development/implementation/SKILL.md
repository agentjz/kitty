# 实施

目标：把已经收束的方案落到真实代码里，不写空壳，不写假闭环。

## 动手原则

- 跟随现有架构、命名、错误处理和测试风格。
- 优先修改离行为最近的正确边界。
- 小改动保持小；跨模块改动要同步入口、状态、测试和文档。
- 能复用本地工具和已有 helper，就不用新造一套。
- 写实现时同时想验证，不把验证留成最后的猜测。

## 写代码

1. 先改主链路
   - 输入、状态、执行、输出要接通。
   - 不先写装饰性封装。
   - 不留 TODO 当功能。

2. 再补边界
   - 空输入、失败、取消、权限、路径、编码、并发。
   - 只补当前行为需要的边界。
   - 不做旧兼容和假历史。

3. 再补测试
   - 测真实产品行为。
   - 对重要接线写集成式测试。
   - 对复杂纯逻辑写小测试。
   - 测试名写行为，不写口号。

4. 最后同步文档
   - 文档只写当前存在的能力。
   - 不解释已经不存在的旧结构。
   - 命令、路径、功能名必须和代码一致。

## 禁止事项

- 不写空实现、空组件、空 handler。
- 不写只为了测试通过的分支。
- 不吞错误。
- 不把状态散落到多个事实源。
- 不做无关重构。
- 不借“以后扩展”引入当前不用的抽象。

## 实施出口

完成后能回答：

- 改了哪条用户路径。
- 哪些文件是主链路。
- 哪些测试保护它。
- 失败时系统会怎么表现。
