# 验证

目标：证明改动真的工作，而不是只证明自己感觉对。

## 验证层级

1. 静态检查
   - 类型检查。
   - lint 或格式检查。
   - 搜索旧入口、旧文案、旧配置是否残留。

2. 自动测试
   - 先跑最相关测试。
   - 再跑项目要求的完整验证。
   - 新增功能要有能失败的测试，不只测存在字符串。

3. 行为检查
   - CLI 看真实输出。
   - Web 看真实页面、请求、连接或 DOM 事实。
   - 后台任务看状态记录和恢复记录。
   - 外部服务没有凭据时，用本地 stub 覆盖协议边界，并说明未做真实联网。

4. 风险复盘
   - 哪些路径没有测到。
   - 哪些外部条件没有覆盖。
   - 哪些改动依赖用户环境。
   - 是否有用户未要求的副作用。

## 验证规则

- 验证失败先读失败事实，再改代码。
- 不把一次绿灯当作所有风险消失。
- 不隐藏未验证的部分。
- 不把“我没法验证”说成“应该没问题”。
- 改动大时跑项目完整验证命令。

## 输出格式

最终回复必须包含：

- 实际运行的命令。
- 结果。
- 没能验证的内容。
- 仍然存在的风险或无风险结论。
