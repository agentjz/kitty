# 开发闭环

目标：把开发任务按“调查研究 -> 实施 -> 验证”推进到底。

## 三阶段

### 1. 调查研究

先使用需求调研和代码调研的方法。

- 确认目标和边界。
- 找入口、链路、状态、输出和测试。
- 判断测试缺口。
- 收束最小改动路线。

没有收束，不动代码。

### 2. 实施

按当前架构做真实改动。

- 改主链路。
- 补必要边界。
- 补测试。
- 同步文档。

不写空壳，不写假实现，不扩大范围。

### 3. 验证

用机器结果关闭任务。

- 跑相关测试。
- 跑完整验证。
- 检查残留旧入口或旧文案。
- 说明没有真实外部服务凭据时的验证边界。

## 节奏

- 小任务可以三阶段压缩，但不能跳过事实、改动、验证。
- 大任务要把计划拆成可完成的块。
- 发现新事实推翻方案时，回到调查研究。
- 用户中途改变目标时，以最新目标重新定边界。

## 完成标准

结束时必须能说清：

- 做了什么。
- 为什么这样做。
- 证据来自哪里。
- 验证怎么跑的。
- 还有什么没验证。
